# AltasCI 子密钥台账手册

**派生协议：** AltasCI/HKDF/v1  
**派生算法：** HKDF-SHA256  
**配套工具：** [altasci-hkdf.sh](https://github.com/phil616/altasci-cryptography-toolkit/blob/main/toolkit/altasci-hkdf.sh)

---

## 1. 管理原则

AltasCI 采用基于 HKDF-SHA256 的确定性密码与密钥派生机制，通过统一的主密钥、派生域及其他派生参数，生成不同应用、基础设施、服务和用户所需的密码与密钥。

密码管理遵循以下基本原则：

- 使用一个高熵的 256 位主密钥作为密码派生的根密钥(名称叫做AltasCI根密钥)。
- 以派生域（Domain）作为密码分类、标识和逻辑隔离的主要手段。
- 不同应用、服务、用户及用途原则上使用不同的派生域。
- 每个派生密码必须建立对应的密码台账。
- 密码台账不保存密码明文或主密钥，仅保存用于恢复密码的派生参数。

本规范中的“密码”泛指通过派生工具生成的应用密码、账户密码、对称加密密钥及其他秘密凭据。

## 2. 主密钥管理

AltasCI根密钥是整个密码管理体系的根秘密。

## 3. 派生域管理

### 3.1 一级域分类

AltasCI 使用以下三个主要的一级派生域：

| 域名称 | 域标识 | 主要用途 |
|---|---|---|
| 公开域 | 无标识或 `public` | 面向外部的应用、公开服务及一般用途 |
| 基础设施域 | `infra` | 数据库、服务器、存储、网络及其他基础设施 |
| 内部域 | `internal` | 内部应用、办公系统、内部 API 及业务服务 |

公开域仅表示应用或服务的归属类别，不代表该域下的密码可以公开。

### 3.2 域命名结构

派生域采用 `/` 作为层级分隔符，推荐结构如下：

```text
<一级域>/<应用ID>/<资源或账户>/<具体用途>
```

根据实际需求，可以省略不必要的层级。

例如：

```text
infra/altasci_db_core
infra/altasci_db_core/admin
infra/altasci_db_core/backup
infra/altasci_db_core/readonly

internal/altasci_office
internal/altasci_office/admin
internal/altasci_office/api
internal/altasci_office/session

public/altasci_blog
public/altasci_blog/admin
```

对于没有一级域标识的公开域，也可以采用以下形式：

```text
altasci_blog
altasci_blog/admin
```

但是，不带标识的域与带 `public` 标识的域属于不同的派生域，不得混用。

例如：

```text
altasci_blog/admin
public/altasci_blog/admin
```

以上两个域会生成不同的密码。新建公开域时，推荐显式使用 `public` 标识，以减少管理歧义。

### 3.3 域命名规则

为保证密码的长期可恢复性，派生域应遵循以下规则：

- 统一使用小写英文字母。
- 允许使用数字、下划线、连字符及 `/`。
- 不使用空格、中文或其他特殊字符。
- 不以 `/` 开头或结尾。
- 不使用连续的 `/`。
- 总长度不得超过 128 字节。
- 不同用途的密码应使用不同的完整派生域。
- 已投入使用的派生域不得随意修改。
- 应用名称发生变化时，不应直接修改已经使用的派生域。

派生域是稳定的密码标识符，而不是用于展示的应用名称。

### 3.4 域前缀

当前派生工具会自动添加以下固定协议前缀：

```text
AltasCI/HKDF/v1/domain/
```

例如，用户输入：

```text
infra/altasci_db_core/admin
```

实际参与 HKDF 运算的 Info 参数为：

```text
AltasCI/HKDF/v1/domain/infra/altasci_db_core/admin
```

密码台账中仅记录用户实际输入的派生域，不需要记录或手动添加协议前缀。

## 4. 应用 ID 管理

应用 ID（Application ID）用于唯一标识一个应用、服务或基础设施实例。

应用 ID 应当保持长期稳定，并且不因应用展示名称、部署地址或版本变化而改变。

例如：

| 应用名称 | 应用 ID |
|---|---|
| AltasCI 核心数据库 | `altasci_db_core` |
| AltasCI 备份系统 | `altasci_backup` |
| AltasCI 对象存储 | `altasci_oss` |
| AltasCI 内部办公系统 | `altasci_office` |
| AltasCI 身份认证系统 | `altasci_idp` |
| AltasCI 官方博客 | `altasci_blog` |

一个应用可以拥有多个密码，但这些密码应归属于同一个应用 ID，并通过不同的派生域进行区分。

应用ID作为人类可读形式展示时候可以不使用lower_case风格，使用url兼容的ID即可，例如 `altasci_oss` 转为 `altasci-oss`。

## 5. 密码派生参数

每个密码由以下参数共同确定：

| 参数 | 默认值 | 说明 |
|---|---|---|
| 主密钥 | 无 | 256 位根主密钥 |
| 派生域 | 无 | 必须指定 |
| 长度 | `32` | 原始密钥字节数 |
| 盐值 | 留空 | 可选的自定义盐 |
| 格式 | `hex` | 密钥输出编码格式 |

相同的主密钥、派生域、盐值及输出长度，将生成相同的原始密钥。

### 5.1 密码长度

派生工具支持以下三种原始密钥长度：

| 长度（字节） | 位数 | Hex 字符数 | Base64 字符数 | Colon 字符数 |
|---|---:|---:|---:|---:|
| 16 | 128 | 32 | 24 | 47 |
| 24 | 192 | 48 | 32 | 71 |
| 32 | 256 | 64 | 44 | 95 |

默认使用 32 字节长度。

仅在目标应用存在密码长度限制或明确的算法要求时，才使用其他长度。

长度指原始密钥的字节数，而不是最终密码的字符数。

不得仅通过改变输出长度来区分不同用途的密码。当前派生协议中，相同主密钥、域和盐生成的短密钥是长密钥的前缀。

### 5.2 盐值

盐值（Salt）是可选的密钥派生参数，主要用于改变派生结果以及支持密码轮换。

一般情况下，使用默认盐即可，无须为每个密码单独生成盐。

当前派生工具的默认盐为：

```text
AltasCI/HKDF-SHA256/default-salt/v1
```

密码台账中的盐值留空，表示使用上述固定协议盐。

如需使用自定义盐，支持以下格式：

```text
text:example
hex:a1b2c3d4
```

推荐使用 32 字节随机盐：

```bash
openssl rand -hex 32
```

生成后添加 `hex:` 前缀，并将完整内容记录到密码台账中。

盐值的管理要求：

- 盐值不属于秘密凭据，可以公开。
- 盐值必须准确记录，不得随意修改。
- 自定义盐必须记录完整的 `text:` 或 `hex:` 前缀。
- 盐值留空与自定义文本盐 `text:default` 不等价。
- 盐值丢失可能导致原密码无法恢复。
- 修改盐值可以用于生成新的密码，但不能解决主密钥泄露问题。

### 5.3 输出格式

密码派生工具支持以下三种格式：

| 格式 | 说明 | 推荐用途 |
|---|---|---|
| `hex` | 十六进制字符串 | 数据库、普通账户、应用密码 |
| `base64` | 标准 Base64 编码 | 对称加密密钥、API、应用配置 |
| `colon` | 使用冒号分隔的十六进制字符串 | 特殊工具及兼容性场景 |

默认使用 `hex`。

例如，同一组原始密钥字节可以表示为：

```text
hex:     a1b2c3d4
base64:  obLD1A==
colon:   a1:b2:c3:d4
```

上述示例仅用于说明编码方式。

输出格式不参与 HKDF 密钥派生过程，只改变最终密钥的表示形式。

不得使用不同的输出格式作为不同密码的隔离手段。若目标应用将编码后的字符串直接作为登录密码，则必须按照台账中记录的格式恢复。

## 6. 密码台账

### 6.1 台账字段

每一个密码必须对应一条密码台账记录。

台账包含以下六个字段：

| 字段 | 推荐英文标识 | 是否必填 | 说明 |
|---|---|---|---|
| 密码或应用名称 | `name` | 是 | 人类可读的密码或应用名称 |
| 所属应用 ID | `app_id` | 是 | 密码所属的应用唯一标识 |
| 域 | `domain` | 是 | 完整派生域 |
| 长度 | `length` | 是 | 原始密钥长度，默认 32 字节 |
| 盐值 | `salt` | 否 | 自定义盐，留空使用默认协议盐 |
| 格式 | `format` | 是 | `hex`、`base64` 或 `colon` |

密码台账应明确其适用的派生协议版本及主密钥归属。这些信息可以作为整个台账的全局属性记录，无须为每条记录增加字段。

密码台账不应包含主密钥或实际派生出的密码。

### 6.2 密码台账示例

| 密码或应用名称 | 所属应用 ID | 域 | 长度 | 盐值 | 格式 |
|---|---|---|---:|---|---|
| 核心数据库主密码 | altasci_db_core | infra/altasci_db_core | 32 | | hex |
| 核心数据库管理员 | altasci_db_core | infra/altasci_db_core/admin | 32 | | hex |
| 核心数据库备份用户 | altasci_db_core | infra/altasci_db_core/backup | 32 | | hex |
| 核心数据库只读用户 | altasci_db_core | infra/altasci_db_core/readonly | 32 | | hex |
| 备份数据加密密钥 | altasci_backup | infra/altasci_backup/encryption | 32 | | base64 |
| 对象存储访问密钥 | altasci_oss | infra/altasci_oss/access | 32 | | hex |
| 内部办公系统管理员 | altasci_office | internal/altasci_office/admin | 32 | | hex |
| 内部办公系统会话密钥 | altasci_office | internal/altasci_office/session | 32 | | base64 |
| 身份认证系统签名密钥 | altasci_idp | internal/altasci_idp/hmac | 32 | | base64 |
| 官方博客管理员 | altasci_blog | public/altasci_blog/admin | 32 | | hex |

### 6.3 台账存储

密码台账可以存储于腾讯文档或阿里云文档。命名为 `AltasCI派生密码台账` 。

## 7. 密码创建流程

创建一个新密码时，按照以下流程操作：

1. 确定密码所属的应用及应用 ID。
2. 确定密码属于公开域、基础设施域或内部域。
3. 根据实际用途确定完整派生域。
4. 检查台账中是否存在相同的派生域。
5. 确定密码长度，默认使用 32 字节。
6. 确定盐值，默认留空。
7. 确定输出格式，默认使用 `hex`。
8. 将上述参数登记到密码台账。
9. 使用 `altasci-hkdf.sh` 派生密码。
10. 将派生密码配置到目标应用，并验证其可用性。

例如，为 AltasCI 核心数据库的 admin 用户创建密码：

```text
密码名称：AltasCI 核心数据库管理员
应用 ID：altasci_db_core
域：infra/altasci_db_core/admin
长度：32
盐值：留空
格式：hex
```

执行派生工具：

```bash
sudo bash ./altasci-hkdf.sh
```

依次输入：

```text
主密钥：<输入主密钥>
派生域：infra/altasci_db_core/admin
Salt：<直接回车>
输出密钥长度：32
输出格式：hex
```

将生成的密码配置为目标数据库用户的密码。

## 8. 密码恢复流程

密码丢失或需要重新获取时，不需要从其他应用中提取密码，也不需要重置原有密码。

恢复流程如下：

1. 在密码台账中查找对应的密码记录。
2. 确认该台账使用的主密钥和派生协议版本。
3. 启动密码派生工具。
4. 输入主密钥。
5. 按照台账输入域、盐值、长度及格式。
6. 获取与原始密码相同的派生结果。

密码恢复过程中，不得擅自更改任何派生参数。

## 9. 密码轮换

### 9.1 单个密码轮换

当某个应用密码需要定期轮换或发生泄露时，推荐保持原派生域不变，通过更换自定义盐生成新密码。

轮换前：

```text
域：infra/altasci_db_core/admin
长度：32
盐值：留空
格式：hex
```

轮换后：

```text
域：infra/altasci_db_core/admin
长度：32
盐值：hex:<新生成的32字节随机盐>
格式：hex
```

轮换流程：

1. 备份当前密码台账记录。
2. 生成新的随机盐。
3. 使用新盐派生新密码。
4. 在目标应用中替换原密码。
5. 验证新密码可用。
6. 更新密码台账。
7. 撤销旧密码或旧凭据。
8. 保留必要的历史派生参数。

对于数据加密密钥，不得仅修改盐值并直接替换旧密钥。必须完成数据重新加密，或保留旧密钥的派生参数以保证历史数据可解密。

### 9.2 主密钥轮换

当主密钥泄露或需要进行整体密钥体系迁移时，应生成新的主密钥，并重新派生相关密码。

主密钥轮换涉及整个密码体系，需要制定独立的迁移计划。

仅修改派生域或盐值不能消除主密钥泄露带来的风险。
